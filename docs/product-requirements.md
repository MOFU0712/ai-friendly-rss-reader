# プロダクト要求定義書

## プロダクトビジョンと目的

RSSフィードを快適に消費するための軽量Webアプリケーション。
既存サービス（Feedly等）の「既読が戻る」「UIが重い」問題を解消し、
**「気になった記事をまとめてAIに渡す」ワークフロー**を中心に設計する。

-----

## ターゲットユーザーと課題・ニーズ

### プライマリユーザー

- 自分自身（ITエンジニア・AI活用推進）
- 将来的に同じワークフローを持つ技術者・情報収集者への公開も視野に入れる

### 課題

|課題            |現状       |本アプリでの解決             |
|--------------|---------|---------------------|
|既読記事が繰り返し表示される|Feedlyで頻発|サーバーサイドで記事IDを管理し重複排除 |
|記事をAIに渡す手順が煩雑 |コピペを繰り返す |チェックした記事をMarkdown一括出力|
|重要サイトが埋もれる    |時系列表示のみ  |お気に入りサイトの優先表示        |

## 成功の定義

- 毎日ストレスなく技術情報をチェックできる
- 気になった記事をワンアクションでAIに渡せる
- 既読記事が重複して表示されない
- 1時間以内に最新記事が反映される

-----

## ユーザーストーリー

```
As a ユーザー
I want to RSSフィードを登録し、記事一覧をカードで確認したい
So that 複数サイトの記事をひとつの画面で把握できる

As a ユーザー
I want to 気になった記事にチェックを入れ、まとめてMarkdown出力したい
So that AIに記事リストを渡してまとめて読める

As a ユーザー
I want to お気に入りのサイトを登録し、そのサイトの記事を優先表示したい
So that 重要な情報を見逃さない

As a ユーザー
I want to 読んだ記事が再表示されないようにしたい
So that 既読管理の手間なく効率よく情報収集できる
```

## 機能要件

### フィード管理

- RSSフィードURLを登録・削除できる
- 登録済みフィードの一覧を確認できる
- フィードにサイト名・優先度（お気に入りフラグ）を設定できる

### 記事表示

- タイトル・概要テキスト・サイト名・公開日時をカード形式で表示する
- お気に入りフィードの記事は上部にグループ表示する
- 既読記事はデフォルト非表示（トグルで表示切替可）
- 記事カードから元記事URLへ遷移できる

### 記事選択とMarkdown出力

- 各カードにチェックボックスを配置する
- 「コピー」ボタンで選択記事を以下のMarkdown形式でクリップボードに書き出す

```markdown
- [記事タイトル](URL)
- [記事タイトル](URL)
```

### フィード更新

- Cron Triggerで1時間に1回、全フィードを取得・パースする
- 記事の重複はGUID（またはURL）で排除する
- 取得エラー時はスキップし、正常なフィードのみ保存する

-----

## 非機能要件

|項目      |要件                             |
|--------|-------------------------------|
|フィード更新頻度|1時間に1回（Cloudflare Cron Trigger）|
|ホスティング  |Cloudflare Pages（無料枠）          |
|DB      |Cloudflare D1（SQLite互換、無料枠）    |
|言語      |TypeScript（フロントエンド・バックエンド統一）   |
|対応デバイス  |デスクトップ優先、モバイル対応（レスポンシブ）        |
|認証      |MVP段階では不要（1ユーザー想定）。将来的に追加      |
|コスト     |MVP段階は無料枠内に収める                 |
