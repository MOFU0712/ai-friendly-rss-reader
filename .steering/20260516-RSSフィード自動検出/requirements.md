# 要件定義 — RSSフィード自動検出

## 背景・目的

RSSフィードの登録を簡単にする。現状はRSSフィードのURLを直接入力する必要があるが、
サイトのURLを貼るだけでRSSフィードを自動的に検出して登録できるようにする。

---

## ユーザーストーリー

- フィード追加フォームにサイトURL（例: `https://zenn.dev/mofu0712`）を貼り付けると、
  RSSフィードURLが自動で検出されてフォームに反映される
- 検出中はローディング表示を行い、ユーザーに処理中であることを伝える
- 複数のRSSフィードが見つかった場合は選択リストを表示する
- RSSフィードが見つからない場合はエラーメッセージを表示し、手動入力にフォールバックする
- 入力されたURLが直接RSSフィードだった場合は検出スキップしてそのまま登録できる

---

## 機能要件

### 検出トリガー
- URLフィールドへの入力が止まってから 500ms 後（debounce）に自動で検出を実行する
- 入力URLが `http://` または `https://` で始まる有効なURL形式である場合のみ検出する

### 検出戦略（優先順）
1. 入力URLをそのままRSSフィードとしてパースを試みる（直接フィードURLの場合）
2. 入力URLのHTMLを取得し `<link rel="alternate" type="application/rss+xml">` / `<link rel="alternate" type="application/atom+xml">` タグを探す
3. 上記で見つからない場合、よく使われるパスを順に試す：
   `/feed`, `/rss`, `/feed.xml`, `/atom.xml`, `/rss.xml`, `/index.xml`, `/feed/rss`

### 検出結果のハンドリング
| 結果 | 動作 |
|------|------|
| 1件のみ検出 | フォームのURLフィールドを自動的に検出したフィードURLで上書き |
| 複数件検出 | フィード候補の選択UIを表示、選択するとURLフィールドに反映 |
| 0件（検出失敗） | エラーメッセージを表示、入力フィールドは変更せず手動入力を促す |

### タイムアウト・エラーハンドリング
- 検出処理全体のタイムアウトは 8 秒
- ネットワークエラーやタイムアウト時はエラーメッセージを表示して手動入力にフォールバック
- 各候補パスへのfetchは並列ではなくHTML取得→パース→共通パス確認の順に実行する（無駄なリクエスト削減）

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 実行環境 | Cloudflare Workers（Node.js非互換、HTMLRewriter利用可能） |
| 既存機能への影響 | RSSフィードURLの直接入力は従来どおり動作する |
| 追加コスト | Cloudflare Workers無料枠内で収まること（fetch回数の最小化） |

---

## スコープ外

- サイトのクロール（リンク先を再帰的に探索）
- RSSフィードのプレビュー（登録前に記事一覧を見る）
- `<a>` タグからのフィードURL推測
